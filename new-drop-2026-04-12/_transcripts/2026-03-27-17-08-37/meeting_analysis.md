### Блок 5: Приватность данных

Виктор поднял важный вопрос: медицинские данные нельзя хранить в базе в первичном виде. Только статистику.

**Согласованный подход:**
- Промежуточные данные (steps) хранятся в **localStorage** (на стороне клиента)
- В базу записываются **только готовые результаты** (анонимизированные)
- При выходе пользователя или истечении JWT -- сервис удаляет сессионные данные
- Оригинальные документы не сохраняются

### Блок 6: Контакт-форма -- дебаты

Геннадий спросил: форма Contact Us -- куда отправляется? В базу или на email?

**Аргументы за email (победили):**
- БД переполнится ненужной информацией (отзывы, предложения -- не критичные данные)
- Для обработки из БД нужен отдельный интерфейс
- Email -- готовый инструмент, не требует дополнительной разработки
- Меньше рисков с инъекциями

Игнат предложил подключить Google-бота, который будет маршрутизировать письма -- но команда решила пока упростить: просто отправка на определенный email через сервис.

Это была самая длинная часть митинга (~30 минут). Скоуп менялся 4 раза:

**Итерация 1:** Auth + Login + Dashboard + Upload (TXT) + Wizard (HIPAA)
*Игнат возразил: "7 девелоперов на одну кнопку аутентификации -- это мало. Но большой бэкенд без фронта -- это риск долгого подключения потом."*

**Итерация 2:** Auth + Login + Dashboard + Upload (TXT) -- без wizard
*Мира согласилась убрать wizard из dev-скоупа первого спринта.*

**Итерация 3:** Contact Us + Auth + Login -- без dashboard
*Игнат настаивал: нам нужна целая компонента (фронт + бэк), чтобы протестировать full-stack. Одна страница лендинга в неделю -- реалистично.*

**Итерация 4 (финальная):** Contact Us page + Get Started кнопка + Auth/Login flow
*Наталья дорисует дашборд параллельно, пока девы делают Contact Us. Wizard -- на следующий спринт.*

**Ключевая мысль Игната:** "Делайте маленькую часть от дизайнера, утверждайте через Людмилу, берите в работу. Пока мы пилим эту деталь -- дизайнер рисует следующую. Конвейер не останавливается."

## 5. Agile-анализ (уровень CTO)

### Есть ли понимание продукта?

**Частичное.** Команда понимает верхнеуровнево: "портал для анонимизации медицинских данных". Но бизнес-логика непрозрачна. Только Игнат попытался выстроить цепочку: "Дилеры получают пациентов, пациенты получают дилеров, это SaaS-платформа." Остальные спросили: "А где это описано?" -- и не получили чёткого ответа. Нет product vision документа. Нет user stories. Нет personas.

### Есть ли backlog?

**Нет.** Мира пообещала создать Jira завтра. На момент митинга backlog -- это устное обсуждение. Нет ни одной записанной user story. Нет story points. Нет prioritization framework.

### Есть ли ownership?

**Фрагментарно.**
- Наталья четко владеет дизайном (и дает конкретные сроки)
- Игорь взял file upload
- Игнат де-факто техлид, но не назначен
- Остальные 4 разработчика -- без задач, без ownership

### Есть ли Definition of Done?

**Нет.** Никто за 1.5 часа не сказал, что значит "сделано". Code review? Тесты? Деплой? Демо? PR merged?

### Есть ли синхронизация между ролями?

**Слабая.**
- Дизайнер и девелоперы обсуждают вместе (хорошо)
- Но PM не имеет технического бэкграунда и не может оценить задачи (просит объяснить каждый шаг)
- Клиент коммуницирует хаотично (удаляет сообщения, нет расписания)
- Нет промежуточного звена между клиентом и командой (нет product owner)

---

### Что работает

1. Команда пытается самоорганизоваться и достичь консенсуса
2. PM (Мира) считает capacity, закладывает буфер рисков
3. Наталья дает конкретные estimate'ы ("логин -- понедельник, дашборд -- среда")
4. Игнат мыслит стратегически: "предлагать, а не спрашивать", "маленькие куски", "конвейер"
5. Команда правильно определила главный bottleneck -- утверждение дизайна

### Что сломано

1. **Sprint planning хаотичный.** Скоуп менялся 4 раза за один митинг. Нет подготовленного backlog, нет pre-estimation.

2. **Нет Definition of Done.** Никто не знает, когда задача считается завершённой.

3. **Нет техлидства.** 7 full-stack разработчиков дебатируют архитектуру в общем звонке по 30 минут. Неэффективно.

4. **Velocity = 0.** Первый спринт. Нет исторических данных. Буфер 20% -- произвольный.

5. **Клиент-менеджмент реактивный.** Команда спрашивает "а что нам делать?" вместо "мы предлагаем X потому что Y".

6. **PM без технического бэкграунда.** Мира не может оценить задачи самостоятельно. Зависит от каждого разработчика для breakdown'а.

## 6. Архитектура проекта (System Design)

### User Flow (восстановлен из обсуждений)

```
                        [Landing Page]
                             |
                    +--------+--------+
                    |                 |
             [Get Started]     [Contact Us]
                    |                 |
            [Auth: Email Input] [Contact Form]
                    |                 |
           [Magic Link Sent]   [Email to admin]
                    |
           [User clicks link]
                    |
              [Dashboard]
                    |
         +----------+----------+
         |                     |
   [File Upload]        [Analytics]
   (TXT -> Presidio)    (Charts/Graphs)
         |
   [Presidio Processing]
         |
   [De-identified Output]
         |
   [Results to DB] --> [Dashboard Charts Update]
```

### Backend Architecture (NestJS)

```
src/
  auth/
    auth.module.ts
    auth.controller.ts
    auth.service.ts            # Magic Link: генерация, отправка, верификация
    user.service.ts            # Поиск/создание пользователя
    jwt.strategy.ts            # JWT Guard, 1-hour expiry
  file-upload/
    file-upload.module.ts
    file-upload.controller.ts
    file-upload.service.ts     # Валидация файла, передача в Presidio
  presidio/
    presidio.module.ts
    presidio.service.ts        # Интеграция с Microsoft Presidio
                               # Detect entities -> De-identify -> Return results
  contact/
    contact.module.ts          # (или как часть общего модуля)
    contact.service.ts         # Отправка формы на email
```

### Frontend Structure (предположительно React/Next.js)

```
pages/
  index.tsx                    # Landing page
  contact.tsx                  # Contact Us form
  auth/
    login.tsx                  # Email input + "Send Magic Link"
    verify.tsx                 # "Check your email" confirmation screen
  dashboard/
    index.tsx                  # Main dashboard with charts
    upload.tsx                 # File upload interface
components/
  Header.tsx                   # Sticky header с "Get Started" кнопкой
  ContactForm.tsx
  Charts/                      # Графики аналитики
  FileUploader.tsx
```

### Data Flow

```
1. User uploads TXT file
   --> POST /api/upload (multipart/form-data)
   --> Backend: file-upload.service validates (size, type, encoding)
   --> Backend: presidio.service.analyze(fileContent)
       --> Presidio detects entities: [name, SSN, phone, address, date_of_birth, ...]
       --> Presidio de-identifies: replaces with synthetic/masked data
   --> Backend: saves ONLY anonymized results + entity statistics to DB
   --> Backend: DELETES original file from memory
   --> Response: { entities: [...], stats: {...}, anonymizedPreview: "..." }
   --> Frontend: renders charts on dashboard
```

### Технические решения, которые НЕ приняты (но нужны)

| Вопрос | Варианты | Рекомендация (как senior) | Обоснование |
|--------|----------|--------------------------|-------------|
| База данных | PostgreSQL / MongoDB / SQLite | **PostgreSQL** | Медицинские данные = ACID compliance. Реляционная модель для users + results |
| ORM | TypeORM / Prisma / MikroORM | **Prisma** | Лучший DX, type safety, миграции из коробки |
| Хранение JWT | Cookie / localStorage | **HttpOnly Secure Cookie** | XSS-protection критична для медицинского портала |
| Хранение файлов | Диск / S3 / только RAM | **Только RAM (buffer)** | Не сохранять оригинал. Обработал -- удалил |
| Email-сервис | Nodemailer / SendGrid / Resend | **Nodemailer + Gmail** | MVP. Бесплатно. Достаточно для тестового emailа |
| State management | Redux / Zustand / Context | **Zustand** | Легковесный, достаточный для этого масштаба |
| Графики | Chart.js / Recharts / D3 | **Recharts** | React-native, простой API, достаточно для 3-5 метрик |
| Деплой | Vercel / Railway / Docker | **Docker + Railway** | Free tier, NestJS-friendly, единый деплой |

### Security (HIPAA-контекст)

| Требование | Статус | Примечание |
|------------|--------|------------|
| Raw data не в БД | Согласовано устно | Нужно формализовать в коде (in-memory processing only) |
| JWT expiry 1 час | Из requirements | Реализовать + auto-redirect на логин при истечении |
| Нет "Remember me" | Из requirements | Не сохранять refresh token |
| Данные сессии удаляются при выходе | Обсуждалось (Виктор) | Нужен cleanup-сервис или middleware |
| Input validation | Геннадий поднял, команда не решила | **Критично** -- sanitize всех input'ов |
| HTTPS only | Не обсуждалось | Обязательно для HIPAA |
| Audit log | Не обсуждалось | Для HIPAA compliance может потребоваться |
