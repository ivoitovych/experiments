# Комплексний аналіз нового дропу — 2026-04-28

## Резюме

Цей звіт аналізує **новий дроп розробки від 28 квітня 2026 року**, який охоплює другий спринт команди Orange та початок планування третього спринту. Дроп містить: оновлені snapshot-и бекенду (`orange_anonymization_be-dev`) та фронтенду (`orange_anonymization_fe-develop`), документ Sprint Demo від 23 квітня, та транскрипції двох мітингів (24 та 27 квітня).

**Загальний прогрес: ~55-60% (з ~25% станом на 12 квітня)**

Команда здійснила **серйозний стрибок у функціональності**. На фронтенді побудований повний 4-кроковий Wizard де-ідентифікації, заповнений Redux store з двома slice (auth + jobs), redux-persist, виправлено TokenPage, реальні користувацькі дані замість заглушок. На бекенді з'явились JobsModule (645 рядків), DashboardModule, інтеграція з Presidio, генерація PDF-звітів, JWT verify flow, повна Swagger-документація.

**Однак є критичні проблеми:**
1. **Presidio integration не працюватиме у runtime** через помилку в ключах конфігурації (читається `'ANALYZER_URL'` замість `'PRESIDIO_ANALYZER_URL'`)
2. **Email service впаде на старті** через аналогічну помилку (`'SMTP_HOST'` замість `'MAIL_HOST'`)
3. **Нуль тестів** — як на бекенді, так і на фронтенді (вже третій спринт без тестів)
4. **Дві конкуруючі JWT guards** з різною формою payload — race condition
5. **Розбіжність entities ↔ migrations** не вирішена з квітня 12
6. **Дашборд та синтетичні дані** залишаються заглушками
7. **Деплой на Heroku досі заблокований** через 2FA Людмили

Sprint 2 demo пройшов 23 квітня (без Ігната). Sprint 3 фокусується на технічному боргу: тестинг, завершення кроку 4 wizard, Presidio конфігурація, GDPR логіка.

## 2. Sprint 2 Demo (23 квітня) — що було продемонстровано

**Учасники:** Людмила, Наталія, Луїза, Олександр

**Примітка:** Ігнат був ВІДСУТНІЙ на демо (підтверджено в транскрипції 24 квітня: "Я вчора не був на демо").

### Що показала Наталія (дизайн Results page)

- Сторінка результатів після "Analyze": заголовок документу + status bar (entity count, score)
- Зліва — оригінальний документ з підсвіченими ідентифікаторами
- Справа — список знайдених сутностей, сортування, filter chips
- Chips відображають **тільки типи сутностей, що реально знайдені** (не всі 18 типів HIPAA)
- Hover-дії на entity картках: **Edit** та **Exclude**

### Що показала Луїза (фронтенд)

- Оновлений лендінг: пошук, статистичні блоки, compliance frameworks, FAQ
- Auth flow: sign in → email verification → dashboard
- Edge cases: expired token (помилка), nonexistent route (404)
- API документація

### Що показав Олександр (Wizard де-ідентифікації)

1. **Step 1:** Framework selection — поки тільки HIPAA
2. **Step 2:** Text input або file upload (з підтримкою reconnect при обриві)
3. **Step 3:** Method choice — Safe Harbor (фіксований набір) або Expert Determination (кастомізовано)
4. **Step 4:** Strategy (default: Redact) + language (default: English) → Analyze → results page з copy/download

### Зворотний зв'язок Людмили (рішення з демо)

| Питання | Рішення |
|---------|---------|
| Edit entities | **Відкласти** — немає чіткого use case, більше для синтетичних даних |
| Exclude entities | **Залишити** — корисно та інтуїтивно |
| Accordion в settings | **Замінити на dropdown** — занадто багато moving parts |
| Contact Form | **Додати email-підтвердження** — стандартна практика |
| Results page | **Переробити за Figma** (дизайн не був готовий до демо) |
| PR review | **Відновити з сьогодні** — процес не дотримувався |

Людмила також сказала Наталії: треба показати **усі 18** entities на екрані, не тільки знайдені; та запитала про мобільну версію dashboard (що було несподіванкою для Наталії).

### Sprint 2: завершено vs не завершено

**✅ Завершено / продемонстровано:**
- Auth FE↔BE flow (sign in, email verification, dashboard)
- Wizard кроки 1-3 переважно зроблені
- Дизайн Results page (Наталія)
- Лендінг redesign з FAQ
- Edge cases (expired token, 404)
- API документація

**⚠️ Не завершено / частково:**
- **Step 4 wizard неповний** ("не зроблений до кінця" за словами Олександра 24 квітня)
- **Тести** — Олександр визнав: "локально є якісь тести, але вони не покривають весь проект"
- **Presidio інтеграція** описана як "Працює, але працює так собі. М'яко кажучи, **диряво**"
- Інші frameworks крім HIPAA — відкладено
- Dashboard — відкладено (був P3)
- Contact Form email-підтвердження — без власника
- Бекенд технічний борг навколо input/output/result сторінок
