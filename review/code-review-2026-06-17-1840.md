## 2. Executive summary

repo**: a single structural source of truth (`scaffold.ENTRIES`) drives the
build, the renderer-bug knowledge is codified into lint rules that each trace

two fact-check subsystems is currently red and unwired. None of this affects
the **primary** GitHub render target, which is correct and verified.

## 3. Findings

### HIGH

#### H1 — mdBook build renders thin-spaces and norm-bars incorrectly (silently)

**Where:** `scripts/build_book.py`, `_destub_math()` (lines 46–50).

**What.** The GitHub-portable manuscript writes a doubled backslash inside
math so that GitHub's one-layer backslash-eating leaves the correct single
escape for MathJax. `tools/lint.py` *enforces* this: it rejects bare `\,` and
`\|` and requires `\\,` / `\\|` (and `\\\\`, `\\{`, `\\}`). For the mdBook
build, `mdbook-katex` extracts math spans **before** any markdown
backslash-eating, so the build must itself undo the doubling. But
`_destub_math` only undoes three of the five forms:

```python
body = body.replace("\\\\\\\\", "\\\\")   # \\\\ -> \\   (row break)
body = body.replace("\\\\{", "\\{").replace("\\\\}", "\\}")  # set braces
# MISSING: \\,  -> \,   (thin space)
# MISSING: \\|  -> \|   (norm bar)
```

The manuscript contains **507** occurrences of `\\,` and **211** of `\\|`
inside math. In the mdBook output KaTeX therefore receives `\\,` and `\\|`,
where `\\` is KaTeX's *newline/row-break* command — so a thin space renders as
a spurious line break followed by a comma, and a norm bar `\\|v\\|` renders as
line-break-bar fragments.

**Why it's dangerous: it fails silently.** `\\` is *valid* KaTeX, so it
produces **no `katex-error` span** — and "zero `katex-error` spans" is exactly
the build's correctness gate (per the module docstring and `HISTORY.md`
§10.5). The math renders *wrong* while the build reports *clean*.

**Verification (run in this review):**

```
$ python3 -c "import sys; sys.path.insert(0,'scripts'); from build_book import _destub_math; print(repr(_destub_math(r'\\,')))"
'\\\\,'      # i.e. \\, is left unchanged; KaTeX will see a row-break + comma
```

**Confidence.** The *input handed to KaTeX is provably wrong*. I could not run
the full `mdbook build` (no `mdbook` binary in this environment) to capture the
rendered HTML, so the final visual symptom is inferred from KaTeX semantics,
not screenshotted. Confirm with one real build.

**Impact.** Secondary render target only (GitHub primary path is correct).
But it is the offline/PDF/EPUB path the project intends to publish, and the
failure is invisible to the existing gate.

**Recommendation.**
1. Add the two missing replacements to `_destub_math`:
   `body = body.replace("\\\\,", "\\,").replace("\\\\|", "\\|")`.
   (Order matters only relative to the `\\\\`→`\\` rule; do the 4→2 row-break
   replacement first, then the comma/bar, to avoid a `\\\\,` being mis-split.
   Worth a unit case for `\\\\,` adjacency.)
2. Close the coverage gap that hid it — see **L1**.

### MEDIUM

#### M1 — `factcheck_anchors.py` is currently failing and is unwired

**Where:** `scripts/factcheck_anchors.py`; Makefile (absence).

`make`-able? No. Running it directly today:

```
$ python3 scripts/factcheck_anchors.py
...
FAIL: 22 problem(s) across 52 files
```

The 22 are **stale anchors**: v1 interim-format fact-check mirror files whose
quoted manuscript snippets no longer match the (correctly edited) manuscript —
e.g. `01-background-and-self-check.md`, `17-complexity-theory.md` (3 stale),
`23-...-tooling.md` (3 stale). This is the tool *working as designed* (it
detects drift), but:

- it is **not wired into any Make target or CI**, so the red state is
  invisible unless someone runs it by hand;
- two fact-check systems now coexist — the **v1 anchor** system
  (`factcheck_anchors.py`, currently red) and the **v2 card** system
  (`factcheck_lint.py`, green: `PASS: 0 lint problem(s), 0 stale, across 3
  card(s)`). `HISTORY.md` lists the v1→v2 migration as an open thread.

**Recommendation.** Decide the migration's fate explicitly: either (a) finish
migrating the 47 v1 files to v2 cards and delete `factcheck_anchors.py`, or
(b) if v1 anchors are to remain the coverage net during migration, make the 22
stale anchors a tracked worklist and re-anchor them. Until then, do **not**
wire `factcheck_anchors.py` into a blocking CI gate (it would be permared);
wire `factcheck_lint.py` (green) instead.

#### M2 — No continuous integration; every guard rail is manual

**Where:** repository (`.github/workflows/` absent).

`make lint`, `scripts/build_book.py --selftest`, `make check-examples`, and the
fact-check linters are all excellent — and all **opt-in**. Nothing prevents a
commit that breaks lint or the build selftest from landing; the project relies
on the author remembering to run them (and, in practice, on the assistant
doing so each turn). The renderer-bug lint is precisely the class of regression
a CI job should catch on every push.

**Recommendation.** Add a minimal GitHub Actions workflow running, on PR/push:
`python3 tools/lint.py`, `python3 scripts/build_book.py --selftest`,
`python3 scripts/generate_index.py` (it `sys.exit(1)`s on unresolved terms),
and `python3 scripts/factcheck_lint.py`. The figure/example/screenshot jobs
need Qiskit/Playwright and can be a separate, non-blocking workflow.

#### M3 — `scaffold.py` README/STYLE generators have silently drifted from the live files

**Where:** `scripts/scaffold.py` — `render_readme()`, `render_style()`, and the
module docstring ("Generates: README.md (master TOC), STYLE.md
(conventions)…").

`main()` writes these via `write_if_missing`, so there is **no clobber risk** —
good. But the live `README.md` and `STYLE.md` have been hand-maintained well
past what these functions emit (the live README carries the full TOC, license
split, and mdBook toolchain matrix; the live STYLE carries the
signpost-not-prerequisite cross-reference policy). The generators are now
**stale, misleading dead code**: anyone who trusts the docstring and runs a
fresh scaffold on an empty tree would regenerate a *regressed* README/STYLE.

**Recommendation.** Either delete `render_readme`/`render_style` (and correct
the docstring to "generates chapter stubs only; README and STYLE are
hand-maintained"), or demote them to a clearly-labelled `--bootstrap-only`
path. The `ENTRIES`-driven README TOC is still genuinely useful — if it is
meant to stay authoritative, generate the **TOC section** into README via
markers rather than owning the whole file.

### LOW

#### L1 — `build_book.py` selftest under-covers the escape forms it protects

The selftest (lines 160–166) exercises only `\\\\` (matrix row break) and
`\\{` (set brace). It does **not** test `\\,` or `\\|` — which is exactly why
**H1** went unnoticed. A selftest that asserted the round-trip for *all five*
lint-enforced forms would have caught H1 at authoring time.

**Recommendation.** Add `\\,`→`\,` and `\\|`→`\|` cases (paired with the H1
fix). Consider deriving the protected-form list once and sharing it between
`tools/lint.py` and `build_book.py` so the two can never disagree about which
forms exist.

#### L2 — `factcheck_lint.py` verdict-counting expression is convoluted and leaks keys

Line 127:

```python
counts[status] = counts.get(status, 0) + 1 if status in VERDICTS else counts.get(status, 0)
```

For an empty or invalid `status` this still executes `counts[status] = ...`,
creating a stray dict key (e.g. `counts[""] = 0`). It is harmless (the
dashboard prints only the four known verdicts) but obscure. Replace with the
obvious guard:

```python
if status in VERDICTS:
    counts[status] += 1
```

#### L3 — `phases.py` `PHASE_BY_FILE` is missing the Historical Prelude

`00-historical-prelude.md` is absent from `PHASE_BY_FILE`. No live impact:
`generate_progress.py` reads the phase from each file's status block (the
prelude self-reports Phase 1), and `scaffold.py` only consults `PHASE_BY_FILE`
when creating a *missing* stub. But a re-scaffold of a fresh tree would render
the prelude stub with `Phase: ?`. Add the entry for consistency.

#### L4 — ~50 lines of Playwright "math-wait" logic duplicated across two tools

`tools/screenshots.py` (lines 98–139) and `tools/render-gist.py` (lines
113–153) carry near-identical `wait_for_function(... mjx-container, g-math,
math, .katex ...)` + timeout-diagnostic blocks. Any fix to GitHub's math-render
detection must be made in two places. Extract a shared
`tools/_gh_math.py::wait_for_math(page)` helper.

#### L5 — `scripts/retrofit_status.py` is dead one-shot migration code

Its target, `> *Status: stub — to be drafted.*`, no longer exists anywhere in
`book/` (confirmed by grep). The script can only ever report "0 files updated".
Remove it (it lives in git history if ever needed), or move it under a
`scripts/migrations/` attic with a dated note.

#### L6 — Shebang / executable-bit inconsistency across all 14 Python entry points

Every `scripts/`, `tools/`, `figures-src/`, and `examples/` Python file starts
with `#!/usr/bin/env python3` but **none** has the executable bit set. They are
all invoked as `python3 path.py` or via `make`, so the shebang is purely
decorative. Pick one convention: drop the shebangs, or `chmod +x` and document
direct invocation. (Cosmetic, but it is a uniform 14/14 mismatch.)

#### L7 — `factcheck_lint.py` usage docstring omits `--strict-stale`

The module docstring's `Usage:` line shows `[--dashboard]` only; the code also
honours `--strict-stale` (line 86). One-line doc fix.

## 4. Strengths worth preserving

These are deliberate, load-bearing design choices a future refactor should not
casually undo:

- **Single structural source of truth.** `scaffold.ENTRIES` is the one place
  chapter order/metadata live; `build_book.py` imports it for `SUMMARY.md` and
  nav, and the build selftest *asserts* the SUMMARY lists all 48 file entries
  (`summary.count("](book/") == len(file_entries())`). This is the right
  backbone.
- **Renderer-bug defense-in-depth.** Each lint rule in `tools/lint.py` maps to
  a numbered bug in `docs/github-markdown-math-bugs.md`, itself justified by a
  labelled cell in `docs/render-tests/math-context-matrix.md`. The build is
  verifiable headlessly (zero `katex-error` spans). This is a mature,
  well-documented system — H1 is a gap *within* it, not an absence of it.
- **Idempotent generators.** Running `generate_progress.py` and
  `generate_index.py` during this review left the tree byte-clean
  (`git status` empty). `generate_index.py` correctly `sys.exit(1)`s on any
  unresolved term — a real guard, not a courtesy.
- **Verdict ⟂ freshness in the fact-check cards.** `factcheck_lint.py`'s
  separation of a stored human verdict from a computed staleness flag (never
  written back) is a genuinely good design for keeping perishable claims
  honest without auto-demoting verified work.
- **Deterministic figures.** `svg.hashsalt` pinned and SVG `Date` metadata
  stripped, so regenerating an unchanged circuit yields a byte-identical file —
  diffs stay meaningful.
- **Executable, deterministic examples.** `examples/*.py` use
  `StatevectorSampler`/`Statevector` (no network, no shot-noise surprises) and
  are run end-to-end by `check_examples.py` — snippets are tested, not asserted.
- **Operationally careful Makefile.** Fresh-OS prerequisite detection
  (`ensurepip`, `playwright install-deps`), a fail-safe `precheck-chromium`
  that prints the exact remedy, and a `render-gist` failure path that
  *preserves* the gist for inspection rather than deleting evidence.
- **Hygiene.** No secrets or tokens in any tool; `.gitignore` covers Python
  artifacts, venvs, `book-build/`, and `.artifacts/`; `from __future__ import
  annotations` + `pathlib` + a `ROOT`-anchored path discipline are used
  consistently.
