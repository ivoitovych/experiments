## Частина 1. Вступ та огляд продукту (~3 хв)

**Хто презентує:** PM або Ігнат (техлід)

### Що сказати:
- Назва: Clinical Data De-Identification Portal
- **Проблема:** лікарні та дослідницькі установи потребують обмінюватися медичними даними, але закон (HIPAA, GDPR) забороняє розкривати персональну інформацію пацієнтів
- **Рішення:** веб-платформа, яка автоматично знаходить та маскує персональні дані (імена, SSN, дати, адреси) у клінічних текстах
- **Підтримувані стандарти:** HIPAA (Safe Harbor, Expert Determination), GDPR, UK DPA, Swiss FADP
- **Цільова аудиторія:** лікарні, клініки, дослідницькі інститути

### Слайд/екран:
- Схема користувацького потоку: Ввести текст → Обрати фреймворк → Налаштувати → Отримати анонімізований результат
- Логотип / назва проєкту

## Частина 2. Архітектура та технічні рішення (~4 хв)

**Хто презентує:** Ігнат або Ігор

### Що показати:

**Діаграма архітектури:**
```
React 19 (Vite)  ←→  NestJS 10 (TypeORM)  ←→  MySQL 8
                                            ←→  Presidio Analyzer (Docker)
                                            ←→  Presidio Anonymizer (Docker)
```

**Ключові технічні рішення:**

| Рішення | Чому |
|---------|------|
| Magic Link (без пароля) | Безпека + простота для медичного персоналу |
| Microsoft Presidio | Відкритий, перевірений інструмент для NER/PII |
| NestJS + TypeORM | Модульна архітектура, строга типізація |
| Redux Toolkit | Передбачуваний стан для складного wizard |
| Heroku + Docker | Швидкий деплой для MVP |
| CI/CD (GitHub Actions) | Автоматична збірка та деплой при кожному пуші |

**Структура бекенд-модулів** (показати дерево):
- AuthModule (Magic Link + JWT)
- UsersModule (entity, upsert)
- EmailModule (SMTP, templates)
- DeIdentificationModule (заплановано)
- JobsModule (заплановано)
