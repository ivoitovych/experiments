**Однак є критичні проблеми:**
1. **Presidio integration не працюватиме у runtime** через помилку в ключах конфігурації (читається `'ANALYZER_URL'` замість `'PRESIDIO_ANALYZER_URL'`)

3. **Нуль тестів** — як на бекенді, так і на фронтенді (вже третій спринт без тестів)
4. **Дві конкуруючі JWT guards** з різною формою payload — race condition
5. **Розбіжність entities ↔ migrations** не вирішена з квітня 12
6. **Дашборд та синтетичні дані** залишаються заглушками
7. **Деплой на Heroku досі заблокований** через 2FA Людмили

Sprint 2 demo пройшов 23 квітня (без Ігната). Sprint 3 фокусується на технічному боргу: тестинг, завершення кроку 4 wizard, Presidio конфігурація, GDPR логіка.

### 3.2 Presidio інтеграція — детально

**Так, Presidio інтеграцію побудовано** — це головна доставка Sprint 2 на бекенді. Pipeline працює через `EventEmitter2` для async обробки.

#### Pipeline (jobs.service.ts:63-177)

```
1. Користувач натискає "Run Analysis"
        ↓
2. POST /jobs/:id/run → emit event 'job.run'
        ↓
3. @OnEvent('job.run') processJob() запускається асинхронно
        ↓
4. Маппінг HIPAA-style entity codes (NAME, SSN, PHONE...)
   → Presidio vocabulary (PERSON, US_SSN, PHONE_NUMBER...)
        ↓
5. Якщо framework='hipaa' AND method='Safe Harbor':
   → Розширення до всіх 18 HIPAA ідентифікаторів
        ↓
6. Виклик analyzer:
   POST {analyzerUrl}/analyze
   {text, language, entities, score_threshold}
        ↓
7. Конвертація стратегій (Replace/Redact/Hash/Mask) → Presidio операторів
        ↓
8. Виклик anonymizer:
   POST {anonymizerUrl}/anonymize
        ↓
9. Збереження: anonymizedText, processingTime, analysisMetadata
        ↓
10. 5-хв watchdog timeout → marks FAILED якщо застряг
```

#### Ентітайп маппінг (HIPAA → Presidio)

```typescript
{
```

## 8. Критичні ризики та блокери

### 🔴 Критичні (показ-стопери)

#### 1. Presidio integration не працюватиме у runtime
- **Причина:** Конфіг ключі `'ANALYZER_URL'` / `'ANONYMIZER_URL'` не існують. Правильні ключі — `'presidio.analyzerUrl'` / `'presidio.anonymizerUrl'`.
- **Наслідок:** Кожен job → ServiceUnavailableException. **Ядро продукту не функціонує.**
- **Виправлення:** 1 рядок коду в `presidio.service.ts:22, 55`.
- **Власник:** Sasha (Олександр)
- **Дедлайн:** ASAP (день 1 Sprint 3)

#### 2. Email service впаде на старті
- **Причина:** `getOrThrow('SMTP_HOST')`, але env має `MAIL_HOST`.
- **Наслідок:** Application crash on startup якщо EmailSenderService інстанціюється.
- **Виправлення:** 1 рядок коду в `email-sender.service.ts:31`.

#### 3. Vision продукту не сформульований
- **Цитата Олександра:** *"Ретавера самого проєкту немає. Будуємо, типу, як в тумані"*
- **Наслідок:** Розробники приймають рішення без alignment, дизайн нестабільний, scope drifts
- **Власник:** Людмила (мала би мати) / Луїза (наразі fills the gap)
- **Дія:** Створити product requirements document, узгодити з Людмилою

### 🟠 Високі

#### 4. Нуль тестів — третій спринт поспіль
- **Цитата Олександра:** *"ми вже третій спринт будемо робити розробку, а тестів ще ніяких"*
- **Наслідок:** Кожна нова зміна може зламати існуюче. Регресія неконтрольована. Сумарний технічний борг росте expoнентно.
- **Дія:** Sprint 3 P0 пріоритет. Хоча б базові unit tests для critical paths.

#### 5. Two competing JWT guards
- **Файли:** `auth/guards/auth.guard.ts` (manual) vs `auth/guards/jwt-auth.guard.ts` (Passport)
- **Race condition:** Form payload відрізняється — одна повертає `{sub, email}`, інша `{id, email}`
- **Наслідок:** Якесь з API ламається залежно від routing
- **Виправлення:** Видалити одну guard, мігрувати controllers на одну схему.

#### 6. `originalText` не персистується
- **Файл:** `job.entity.ts:79-81` — поле закоментовано
- **Наслідок:** Якщо worker crashes між accept та process — text втрачено
- **Workaround у FE:** localOriginalTexts в redux-persist sessionStorage (компенсує, але не вирішує BE проблему)

#### 7. Heroku deployment заблокований 3+ тижні
- **Причина:** Людмила не має account permissions для GH_PAT
- **Наслідок:** Команда не може показати продукт реально працюючим
- **Дія:** Ігнат waiting на ще одну call з Людмилою

#### 8. Невирішений entity↔migration drift
- **Файли:** `User` entity має 4 поля, migration створює 10 полів
- **Наслідок:** Production з `DB_SYNCHRONIZE=false` упаде
- **Виправлення:** Додати недостаючі поля в entity, оновити migration якщо потрібно

### 🟡 Середні

#### 9. ReviewAndRun polling без backoff
- **Файл:** `ReviewAndRun.tsx`
- **Ризик:** Якщо job застряг, FE буде бомбардувати BE forever
- **Дія:** Додати exponential backoff та max attempts (наприклад, 30 attempts ≈ 1 хв)

#### 10. Race condition в stepper init
- **Файл:** `CustomizedStepper.tsx:151`
- **Проблема:** `getLatestDraft()` викликає `createJob()` без `await`
- **Наслідок:** Stale state, можливі race conditions

#### 11. DashboardController зареєстровано двічі

- **Виправлення:** Видалити з одного модуля

#### 12. Non-HIPAA frameworks render empty Box

- **Наслідок:** Broken UX для GDPR users (вони бачать порожню сторінку)

Sprint 2 був **продуктивним** — функціонал виріс з ~25% до ~58%. Команда розробила wizard, redux store, auth flow, Presidio integration, PDF reports, session expiration UX. Це реальний прогрес.

**Але є серйозні проблеми:**
1. **Конфіг bugs роблять production code untestable end-to-end** — 1 рядок виправлення на Presidio + 1 на SMTP розблокує тестування
2. **3 спринти без тестів** = накопичення боргу, який стане критичним блокером
3. **Vision не сформульований** — команда будує "in the fog"
4. **Deployment 3+ тижні заблокований**
5. **Розбіжності в коді** (entity↔migration, JWT guards) — наслідок rushed integration

**Sprint 3 правильно фокусується на технічному боргу** — це зріле рішення. Ігнат як driving force на процесах та Олександр як технічний лідер тримають проєкт. Луїза балансує stakeholder management.

**Прогноз:** Якщо Sprint 3 закриє конфіг bugs + базові тести + deployment, Sprint 4 зможе delivery dashboard + GDPR + production-ready release. Якщо ні — продукт залишиться "demo-only" indefinitely.
