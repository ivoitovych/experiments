## Что показали

### Дизайн страницы результатов (Natalia)

После нажатия «Analyze» пользователь попадает на страницу с:

- Заголовком документа и статус-баром (количество обработанных сущностей, score)
- **Слева** — оригинальный документ с подсвеченными идентификаторами
- **Справа** — список найденных сущностей, сортировка, чипы-фильтры

Чипы отображают только типы сущностей, найденные в конкретном документе (не все 18 HIPAA-типов, только реально обнаруженные). При максимальном заполнении добавляется дополнительный ряд.

На карточках сущностей доступны два действия при hover: **Edit** и **Exclude**.

### Фронтенд приложения (Luisa)

- Обновлённый лендинг: поиск, блоки статистики, compliance frameworks, FAQ
- Флоу авторизации: sign in → email verification → dashboard
- Обработка edge cases: истёкший токен (ошибка), несуществующий роут (404)
- Документация API

### Фича де-идентификации (Olexandr)

Пошаговый wizard:

1. Выбор фреймворка — сейчас только **HIPAA**, остальные в следующем спринте
2. Ввод текста или загрузка файла. При разрыве соединения можно вернуться на этот шаг
3. Выбор метода: **Safe Harbor** (фиксированный набор сущностей) или **Expert Determination** (настраиваемый)
4. Выбор стратегии (по умолчанию Redact) и языка (по умолчанию English)
5. Анализ → страница результатов с возможностью копирования и скачивания

## Решения

| Решение | Контекст |
|---|---|
| **Edit сущностей → перенести в следующий шаг** | Нет чёткого use case на текущем этапе; больше подходит для синтетических данных |
| **Exclude сущностей → оставить** | Логически понятен, полезен пользователю |
| **Accordion в настройках → заменить на обычный dropdown** | Слишком много движущихся частей, создаёт путаницу |
| **Contact Form → добавить confirmation email** | Стандартная практика; пользователь должен получать подтверждение получения запроса |
| **Страница результатов → доработать под Figma** | Дизайн не был готов до демо |
| **PR review → возобновить с сегодняшнего дня** | Процесс не соблюдался, восстанавливается |
