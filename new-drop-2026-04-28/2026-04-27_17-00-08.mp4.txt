Підсумок щоденної зустрічі команди: планування спринту, UI-оновлення та деідентифікація

Ключові теми

**Спринт-планування**: Обговорення файлу з декомпозицією задач (макс. 2 коміти, 5-7 файлів на день), розбиття на таски з урахуванням часу; команда перегляне файл у групі та дасть фідбек.

**Деідентифікація ентіті (select/deselect)**: Пояснення логіки — при select ентіті деідентифікується в output (заміна на [редакт.]), при deselect лишається оригінальний текст; бекенд не зберігає/кешує дані, відповідальність на юзері; фокус на client-даних, фільтрація нерелевантного тексту через тести.

**UI-оновлення**: Додано кнопку "Копіювати" текст, кнопка завантаження відредагованого файлу; логіка навігації (назад, New Analysis); обговорення empty state з прикладами/інтуїтивними підказками замість попапу.

**GDPR-логіка**: Почато роботу, виявлено відмінності від поточної (деякі ентіті не можна вручну обирати/прибирати); логіка буде максимально схожою.

**Доступ та GitHub Actions**: Проблеми з ключами від Людмили (немає прав); потрібен GitHub PAT для фронтенд-репо, SSH не спрацює через workflow; схема: опуш через URL + GHA + Docker.

Інсайти та takeaways

Макети деідентифікації не потребують змін — логіка підтверджена (select/de-select як описано).

Тести критичні: проганяти на даних з client-інфо + лор, щоб AI відзначав тільки релевантне.

Навігація/UI: уникати зайвих кнопок (прибрати дубль "назад"), фокус на інтуїтивність (empty state з прикладами); оновлення сторінки скидає до меню аналізу.

GDPR складніший за очікування, але адаптуємо.

Деплой: GHA + PAT обов'язкові, SSH не підходить для GitHub workflow.

Висновки та рішення

Скинути спринт-файл у групу для ревью; завтра детальніше обговорити декомпозицію та зауваження.

Макети/UI не міняти, реалізація — на розробників (питання — тегати).

Пропозиції по empty state/New Analysis обговорити на наступній зустрічі.

GDPR: продовжити роботу з урахуванням відмінностей.

Ключі/доступ: чекати від Людмили, додатково кол для доробки; схема деплою готова.
